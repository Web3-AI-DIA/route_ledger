## 2026-07-02 - Remediation of PII Leakage and Verbose Errors in Firestore Error Handler
**Vulnerability:** The central Firestore error handler `handleFirestoreError` in `lib/error-handler.ts` logged and threw detailed Firestore transaction details, exposing sensitive client PII (such as `email`, `displayName`, and `photoUrl` from the authenticated user context) and revealing internal database schemas to potential client-side consumption.
**Learning:** Error logs and thrown errors should never propagate unfiltered user-specific information or structural database internals. Centralized error handling must sanitize/redact PII and catch database failures, translating them into secure, generic error messages for the client while storing structured, redacted diagnostics internally via centralized Pino logging.
**Prevention:** Always redact sensitive auth attributes (like email, displayName, and profile photo URLs) at the boundary of logging services. Avoid throwing verbose raw errors to the client; instead, log structured metadata securely under the `err` key using a centralized logger (e.g., Pino) and expose only sanitized, generic messages to the outer scope.
